# 架构

```text
行业系统 → OpenAPI / Webhook → 开源平台 → S3 设备协议 → 官方 S3 固件 → 闭源 BSP → 硬件
```

平台核心只负责设备身份、能力、内容任务、事件和插件生命周期，不内置具体行业结论。行业差异放在插件中。

## 第一版数据流

1. 工厂或开发环境注册 S3 设备，获得唯一设备令牌。
2. S3 定期上报心跳并轮询下一条内容任务。
3. 行业系统使用应用密钥向指定设备推送结构化内容。
4. 固件根据 `template + data + screen` 渲染 A/B 屏并确认结果。
5. 后续版本增加按键事件、Webhook、插件安装与模板渲染服务。

## 兼容现有固件

现有固件使用 `/api/render`、`/api/device/<mac>/heartbeat` 等旧接口。它不会直接复制进平台核心，而是由后续 `legacy-adapter` 转换为 v1 任务协议。这样可以保持已售设备兼容，同时不把旧后台的账号与模式实现带入新架构。

## 安全模型

- 设备令牌与应用密钥分离，设备只能访问自身资源。
- 数据库只保存令牌 SHA-256 摘要。
- 生产注册关闭匿名注册，由工厂凭据或一次性激活码发起。
- 插件声明最小权限，不能直接读写核心数据库。
- OTA 二进制必须签名，签名服务不属于开源后台。
