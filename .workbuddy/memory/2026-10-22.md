## 08:35 烧录后复测 + 按键语义确认
- 二进制核验：build/xiaozhi.elf(08:29) 含 "pre-reset BUSY"/"post-reset BUSY"/"192.168.101.69"，源码改于 08:20-08:21 → 烧录版本确含全部改动。

- 判定法：拔掉 FPC2 排线开机，若 pre-reset=1 → 主板 OK（屏/排线/型号问题）；仍 0 → BUSY1(FPC2-9↔GPIO12) 对地短路或引脚被占用。
- 升压泵对称核查：FPC2 用 Q2(AO3400)+L11+U2(MBR0530)+C3，FPC1 用 Q1+L1+U10+C8；GDR/RESE 栅极经 R10/R15(10k) 下拉到 GND（两路一致，非设计缺陷）。
- 按键语义（ssd2683za_s3_board.cc KeyScanTask，pins[0]=KEY+ [1]=KEY_OK [2]=KEY-）：
  * KEY+ 长按 3s = 重新配对：UnbindForReconfig(POST /api/device/<mac>/unbind) + EnterWifiConfigMode
  * KEY- 长按 2s = 仅 EnterWifiConfigMode（换 WiFi，不解绑 → 不会出配对码）
  * KEY_OK 长按 2s = 返回首页
- 解绑/运行模式上报接口均需有效 X-Device-Token（否则 403），解绑失败会落 rebind_pending=1 联网后重试。

## 09:00 长按按键进配网 → httpd_start 失败导致整机重启（已修）
- 现象：长按 KEY-（GPIO46）→ "EnterWifiConfigMode" → 起 softAP 成功 → `E httpd: httpd_server_init: error in creating ctrl socket (112)` → `ESP_ERROR_CHECK failed ... wifi_configuration_ap.cc:245` → abort → 重启。配网热点根本没机会弹出来。
- 根因：**两个 httpd 实例抢同一个控制套接字端口**。esp_http_server 的每个实例都会额外建一个 UDP ctrl socket（绑 127.0.0.1:ctrl_port，默认 `ESP_HTTPD_DEF_CTRL_PORT=32768`，见 esp_http_server.h:24）。本板的 8080 待办编辑器（epaper_todo_web.cc）用 HTTPD_DEFAULT_CONFIG() 没改 ctrl_port，与配网门户（esp-wifi-connect，80 端口）撞车 → 后者 ctrl socket bind 失败 → httpd_start 失败 → 被组件里的 ESP_ERROR_CHECK 打挂。
- errno 112 说明：lwIP errno.h 里 112=EHOSTDOWN，而 lwIP 自身从不 set 该值（EADDRINUSE=98 / ENOBUFS=105 / ENFILE=23），所以打印值是 ctrl socket 创建失败路径上的残留/次生 errno，不必纠结；判据看 "creating ctrl socket" 这一行即可。
- 修复（4 处）：
  1. epaper_todo_web.cc：`config.ctrl_port = 32769`（多实例必须互异）+ `max_open_sockets = 3`（省 socket 配额）；新增 `Stop()`（httpd_stop 前置空句柄防重入），析构改调 Stop。
  2. epaper_todo_web.h：声明 Stop()。
  3. ssd2683za_s3_board.cc：SetNetworkEventCallback 里对 `NetworkEvent::Disconnected` 调 `todo_web_->Stop()`——StartConfigAp() 会先停 station 并广播 Disconnected 再起门户 httpd，所以这是唯一能抢在门户启动前释放 8080 的钩子（WifiConfigModeEnter 是在 config_ap_->Start() 之后才广播的，来不及）。联网后 Connected 分支会自动重启。
  4. managed_components/78__esp-wifi-connect/wifi_configuration_ap.cc：ESP_ERROR_CHECK(httpd_start) 改为「换 ctrl_port 32770 重试，仍失败只打日志并 return」，永不 abort 重启。⚠️ 该目录被 .gitignore 忽略（组件管理器可重新拉取），已有 remember_bssid 等本地改动也在此，重拉需重新打补丁。

## 10:05 KEY+ 重新配网后整机重启（两个根因，均已修）
- 现象：配网成功拿到 IP → `Device token provisioning failed: HTTP 404` → `HttpClient: HTTP connection closed` → `assert failed: xQueueSemaphoreTake queue.c:1713 (pxQueue->uxItemSize == 0)` → abort 重启。调用栈：EspTcp::ReceiveTask → DoDisconnect(false) → HttpClient::OnTcpDisconnected → std::mutex::lock。
- 根因 A（崩溃）：**HttpClient 已析构、TCP 接收任务仍在回调它**。DeviceToken() 拿到 404 后 `return {}`，http unique_ptr 析构 → ~HttpClient → Close() → tcp_->Disconnect()。而 EspTcp::Disconnect() 只要 `connected_==false` 就直接 return（被动断开时接收任务已把 connected_ 置 false），**完全不等接收任务退出**；随后 ~EspTcp 删掉 event_group_。晚一步被调度的接收任务对已释放对象执行 DoDisconnect(false) → disconnect_callback_ → OnTcpDisconnected 上的 mutex_ 是野内存 → 断言 abort。
- 根因 B（404）：`POST /api/device/{mac}/token` 要求 `store.device_exists(mac)`，但 devices 表只有 FIN-TEST-01，真机 MAC 从未登记（`store.register()` 只能经 `POST /api/v1/devices/register` + admin key 调用，固件从没调过）→ 404 → 领不到 X-Device-Token → /api/render 401 → 永远出不来配对码，形成死结。
- 修复（固件，managed_components/78__esp-ml307）：
  1. src/esp/esp_tcp.cc：Disconnect() 改为「connected_ 或 receive_task_handle_ 任一为真就 DoDisconnect(true)」；DoDisconnect 先 `shutdown(fd, SHUT_RDWR)` 再 close（只 close 时 lwIP 不一定及时唤醒阻塞的 recv），且只要有任务句柄就等退出位（原来等待逻辑被包在 `tcp_fd_ != -1` 分支里，被动断开后 fd 已是 -1 → 从不等待）；析构里任务未退出则不删 event_group_。
  2. include/http_client.h + src/http_client.cc：新增 `std::shared_ptr<bool> alive_`，OnStream/OnDisconnected 回调捕获它并在析构时置 false —— 兜底拦住一切「对象已释放仍被回调」的 UAF。
- 修复（后端）：console_api.py `/api/device/{mac}/token` 新增 `_self_enroll()`：未知 MAC 首次领令牌时自动 `store.register()`（建 devices 行 + 6 位配对码，保持未绑定），可用 `XIAOWU_DEVICE_SELF_ENROLL=false` 关闭（产线预登记模式）；store.py 新增 `ensure_claim_code()` 给漏配对码的老设备补发，render_api.py 未绑定分支改用它（原来是 `or "------"`）。
- 补丁固化：managed_components/ 被 .gitignore 忽略，已把 4 个打过补丁的文件（esp_tcp.cc、http_client.cc/h、wifi_configuration_ap.cc）复制到 `firmware/s3/patches/<component>/...`，新增 `patches/apply.sh`（重拉组件后一键恢复）。每次改 managed_components 都要重新 cp 一份。
- 编译：sh .tmp/build.sh build → Project build complete，build/xiaozhi.bin（10:07，0x4270c0）。烧录后设备会自动登记 + 屏幕显示配对码。
