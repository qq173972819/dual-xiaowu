整套接入分成两个阶段，它们发生在不同时机、不同网络位置。看懂这张图，后面的步骤都是填空。

01注册设备，换取 deviceToken

在贵方服务器上执行，每台设备一次。API Key 由我们通过安全渠道单独交付，请勿写入固件、前端或代码仓库。

请求server → LightAcade
# deviceSerial 用设备 MAC 地址（推荐，与固件上报的 Device-Id 一致，便于排查）
curl -X POST https://api.aioneschool.com/api/partner/v1/devices \
  -H "X-Api-Key: <贵方 API Key>" \
  -H "Content-Type: application/json" \
  -d '{"deviceSerial": "AA:BB:CC:DD:EE:FF"}'
响应 200deviceToken 明文只出现这一次
{
  "deviceId": "7c4ce179-c36d-479a-a976-9718aed1d197",
  "deviceToken": "MUvYn9bHBHDNkonLeulrK5Ws_ylJcvNGlFegMn5JcGU"
}

deviceSerial 我们只校验三条：非空、不超过 120 字符、同一把 API Key 下不重复。格式不限，用 MAC 地址是推荐做法——小智固件连接时会自动上报 Device-Id: <MAC>，两边一致后，出问题时用一个 MAC 就能在日志和数据库里定位到同一台机器。

注册接口的返回码

HTTPcode含义与处理
400INVALID_DEVICE_SERIAL序列号为空或超过 120 字符
401INVALID_API_KEYAPI Key 无效或已停用
409DEVICE_SERIAL_EXISTS该 MAC 已注册过。我们不做隐式换绑，以免静默顶掉正在使用的设备；确需重发令牌请联系我们先吊销旧记录
429DEVICE_LIMIT_EXCEEDED已达可注册设备台数上限，联系我们调整
503ORAL_PRACTICE_DISABLED服务维护中，可重试

错误响应统一为 {"error": {"code": "...", "message": "...", "retryable": false}}。

02设备侧配置

固件不用改，只改两项配置：

设备配置device
WebSocket URL    wss://api.aioneschool.com/api/partner/v1/xiaozhi/ws
Authorization    Bearer <deviceToken>   ← 注册接口返回的那串，不是 API Key

小智固件会自动带上 Protocol-Version: 1、Device-Id、Client-Id 三个头，我们记入日志用于排查，不参与鉴权判定——鉴权只认 Authorization 里的 deviceToken。

安全红线：API Key 永远不要写进设备。设备是不可信终端，固件一旦被读出，API Key 泄露意味着全部设备受影响且无法单台止损；而 deviceToken 是一机一码，任意一台出问题我们单独吊销即可，其余设备不受影响。我们的网关在技术上也拒绝 API Key 直连（会返回 4401）。

03会话协议

以下全部是小智标准协议，原生固件已实现。列在这里是为了让贵方在抓包排查时知道每一帧代表什么。

握手

连上后设备先发 hello，我们回 hello。设备需在 10 秒内发出 hello，否则连接关闭。

设备 → 服务端上行音频参数
{
  "type": "hello",
  "transport": "websocket",
  "audio_params": {
    "format": "opus", "sample_rate": 16000,
    "channels": 1,      "frame_duration": 60
  }
}
服务端 → 设备下行音频参数（注意采样率不同）
{
  "type": "hello",
  "transport": "websocket",
  "session_id": "6980c59450ff479890a765da5a574d52",
  "audio_params": {
    "format": "opus", "sample_rate": 24000,
    "channels": 1,      "frame_duration": 60
  }
}

对话中的消息

方向消息含义
设备 →listen / start开始采音，随后持续发送二进制 Opus 帧
设备 →listen / stop暂停采音（会话保持，不结束）
设备 →abort打断当前播报，立即回到聆听状态
设备 →goodbye正常结束本次会话
→ 设备tts / startAI 开始说话，其后的二进制帧即为语音
→ 设备tts / sentence_start带 text 字段，AI 当前句的文字（可上屏）
→ 设备tts / stop本轮播报结束
→ 设备stt带 text 字段，识别到的学生说话内容

语种与学段由我们按贵方 Key 预先配置（当前：英语 / 初中段），设备不需要传，也无法在会话中更改。需要调整请联系我们。

不需要打断指令的那部分

学生说话时的自然打断由服务端的语音活动检测处理，设备无需干预；abort 用于按键、唤醒词这类设备侧主动打断。

04音频格式

方向编码采样率帧长实测码率
上行（麦克风）Opus16 000 Hz60 ms—
下行（扬声器）Opus24 000 Hz60 ms≈ 22 kbps

下行按 60 ms 一帧的固定节拍产出，实测平均 163 字节/帧。

均为单声道。下行采用 Opus 压缩（相较未压缩音频约省 17 倍带宽），设备端按固件自带的播放队列缓冲播放即可，无需额外处理。

05连接被拒：关闭码

握手或鉴权不通过时，我们以 WebSocket 关闭码告知原因：

Close原因处理
4400hello 缺失、超时或音频参数不匹配检查 hello 是否为 opus / 16000 / 单声道 / 60ms
4401令牌无效、设备已被吊销，或误用了 API Key确认 Authorization 填的是 deviceToken
4403服务未开放，或该 Key 尚未配置语种/学段联系我们
4429配额用尽或并发已满见下节，可稍后重试

07联调自检清单

  • 设备能解析域名并建立 TLS 连接（测试环境为境外节点，请确认网络可达）。
  • Authorization 填的是 deviceToken，不是 API Key —— 这是最常见的接入错误，表现为 4401。
  • hello 的四个音频参数与上表完全一致，任一不符都会 4400。
  • 连上后如果只收到文字消息、听不到声音，检查设备是否按 24 kHz 解码下行 Opus（上下行采样率不同）。
  • 对话中途断开，先看关闭码：4429 是配额或并发，其余情况把 MAC 与大致时间发给我们，我们可凭此定位到具体会话。

接入过程中遇到任何问题，请提供设备 MAC 地址 + 发生时间（精确到分钟）+ 观察到的关闭码，我们据此可以直接查到对应的会话记录。
